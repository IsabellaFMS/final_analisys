### 7.3 Environment-specific leftovers

`step2/run_analysis.py:47` hardcodes an absolute Windows path as an R fallback:

```python
fallback = Path(r"C:\Program Files\R\R-4.5.3\bin\Rscript.exe")
```

This is one machine's layout in a deposit meant to be downloaded and run. Drop
the fallback and keep the `shutil.which("Rscript")` lookup with its existing
error message, which already tells the user to install R or fix `PATH`. If a
fallback is wanted, read it from an environment variable (`OPXV_RSCRIPT`) and
document it in `step2/README.md`.

Also at `step2/run_analysis.py:68`: `R_LIBS_USER` is set to
`~/R/win-library/4.5`, again Windows- and version-specific, and it overrides
whatever the user's R installation would use. Set it only when it is already
present in the environment, or remove it.

### 7.4 Documentation that duplicates the code

`step1/docs/analysis.txt` restates what `step1/README.md` and the source files
say, and frames itself as a guide to "reproduce the same logic in another
scenario" — which is not what a deposit documents. It is also the only `docs/`
directory in the repository, so it is inconsistent with the other six steps.

Check it against `step1/README.md` and against the current code. Then either
fold anything it uniquely contains into `step1/README.md` and delete it, or keep
it and bring it in line with the other steps' documentation. Do not leave two
documents describing step 1 differently.

## Consistency checks across the repository

- **Run order.** The root README's dependency sentence (lines 66–68) predates

- **Quoting style.** The step READMEs quote paths with `"…"` (step 3–6) while the
  root README and `step2/README.md` use backticks. Pick one and apply it; this is
  cosmetic, so it goes last and in one pass.
- **Column naming.** `step7/outputs/*.csv` use `Protein_ID`, `step6`'s table uses
  `Accession`, `step5`'s uses `id`. These are published data; do **not** rename
  them. Document the correspondence in the root README instead, since step 8 now
  joins all three.
- **Separators.** `step5` writes `;`-separated CSV, `step6` `;`, `step7` `,`.
  Again published; document, do not change. Spec 04's loaders must handle each
  explicitly rather than relying on sniffing.
